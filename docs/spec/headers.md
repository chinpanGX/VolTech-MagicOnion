# ヘッダーと RPC ごとの設定

## ヘッダー

ヘッダー名はクライアントの `ApiHeaders` と同じにする。サーバーは `Abstractions` に定数を置き、両方を一緒に直す。

| 向き | ヘッダー | 内容 |
| --- | --- | --- |
| リクエスト | `authorization` | `Bearer <token>`。`[SkipAuth]` の RPC には付かない |
| リクエスト | `x-request-id` | 冪等性の対象(`[NoSideEffects]` の付かない RPC)のみ。1〜64 文字、英数字と `-` |
| リクエスト | `x-app-platform` | ios / android / windows / editor。今はログにだけ使い、強制アップデートを足したらその判定に使う |
| リクエスト | `x-app-version` | リリースごとに増やす整数。用途は `x-app-platform` と同じ |
| リクエスト | `x-game-date` | セッションの最初に受け取った日付(YYYY-MM-DD) |
| レスポンス | `x-server-time` | Unix 時間のミリ秒 |
| レスポンス | `x-game-date` | 今のゲーム内の日付 |

## RPC ごとの設定は属性に置く

Rust 版は proto の `idempotency_level` と `skip_auth` で RPC ごとの扱いを決めていた。C# では共有インターフェースの属性で持つ。

| 属性 | 意味 |
| --- | --- |
| `[SkipAuth]` | 認証の検証を省く(トークンを確かめない) |
| `[NoSideEffects]` | 副作用がない。冪等性の対象から外し、読み取り専用のトランザクションで動かす |

`[NoSideEffects]` の付かない RPC は、すべて冪等性の対象にする。

属性は共有インターフェースにだけ付ける。サーバーとクライアント(`RpcSettings`)は、共有インターフェースの属性だけを読み、実装クラスや実装クラスのメソッドに付けた属性は読まない(付けても効かない)。クライアントは実装クラスを知らないので、実装クラスの属性まで読むと、サーバーとクライアントで設定が食い違う。

共有インターフェースは、サービスのクラスが継承する `ServiceBase<T>` の `T`(MagicOnion がそのサービスとして登録するインターフェース)。クライアントの `ApiServiceBase<TService>` の `TService` と同じものになる。実装クラスがほかのインターフェースを実装していても、その属性は読まない。

| 属性 | 付けられる場所 | 効く範囲 |
| --- | --- | --- |
| `[SkipAuth]` | 共有インターフェース、またはそのメソッド | インターフェースに付けたらすべてのメソッド、メソッドに付けたらそのメソッド |
| `[NoSideEffects]` | 共有インターフェースのメソッド | そのメソッド |

- `[SkipAuth]` はクラスに付けられない(付けるとコンパイルエラー)。メソッドには付けられるので、実装クラスのメソッドに付けてもコンパイルは通るが、効かない

## 共通レスポンス項目

`player_diff`・バッジ・通知は、`IApiResponse` を実装した MessagePack の型で返す。
